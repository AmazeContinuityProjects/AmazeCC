# Privacy and inclusion controls

The report consolidates sensitive academic, financial, identity, residential, and activity data into a portable file. Make section inclusion deliberate and visible before export.

## Default inclusion

Include academic identity needed to identify the student, academic performance, grade history, current and historical attendance available from source, exam schedules, curriculum progress, and prediction data with clear labels. Use profile photo only when present and enabled. Do not include DOB, personal contact details, detailed hostel location, finance, library, transport, private notes, or activity-level focus records by default.

## Explicit opt-in sections

Offer separate toggles for:

- Financial record: dues, receipts, wallet ledger, and any actually retained status transitions.
- Hostel and own leave information.
- Library loans/dues and transport status.
- Moodle assignment details and registered event history.
- Personal profile fields beyond name, registration number and academic programme.
- User-entered tasks, notes, and detailed study-session history.

Show a final checklist of selected sections and the report's estimated page count before export. Do not preselect sensitive sections solely because the user requested “all the data.”

## Never include

- Passwords, credentials, auth tokens, cookies, CSRF values, session IDs, API keys, recovery data, or login URLs containing secrets.
- Classmate/friend schedules, names, marks, personal contact details, roommate names, or other students' records.
- Analytics identifiers/events, crash/error logs, bug recordings, sync logs, device identifiers, internal cache keys, app settings, or service configuration.
- Payment gateway links/session identifiers or raw response material that exposes secrets.

## Handling and disclosure

- Keep report generation local to the user's session where possible; do not upload report contents to analytics or third parties.
- JSON exports must apply the same exclusions and opt-in selections as the PDF.
- Clearly identify the report as generated by AmazeCC from data available to the app. It is informational, may be incomplete or stale, and is not an official transcript, attendance certificate, fee receipt, or institutional document.
- Show generated time, source freshness, stale/partial sections and data-through date. Let the user review inclusion settings before creating or sharing the file.
- Use neutral labels and avoid exposing sensitive fields in filenames. A filename can use `AmazeCC-Student-Report-YYYY-MM-DD.pdf` without registration number.
